# SeminaVerbi wiki MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Claude Code a bot-authenticated MCP connection to the six SeminaVerbi wikis plus a skill, data and helper that make its edits follow the house conventions (links, SV templates, category tree with Gospel themes, Cathopedia).

**Architecture:** ProfessionalWiki's `mediawiki-mcp-server` (pinned) does page I/O and Wikibase edits as `SV editor bot`. This repo adds: `config/categories.json` (fields + Gospel themes, six languages) compiled into `Module:SV/Data`; three templates (`SV category tree`, `SV quote`, `SV cathopedia`); `tools/categories` (check/create category pages and their sitelinks); and the `seminaverbi-editor` skill whose reference files are generated from `config/`.

**Tech Stack:** Lua 5.1 (Scribunto) tested with lupa; Python 3.12 (`requests`, pytest); Node (npx) for the MCP server; MediaWiki 1.44 maintenance scripts on the server.

**Spec:** `docs/superpowers/specs/2026-11-17-wiki-mcp-design.md`

## Global Constraints

- Six wikis, codes `en it es fr de pt`; hosts `https://<code>.seminaverbi.bibleget.io`, API at `/w/api.php`. Wikibase repo is `en`; local site IDs are `enwiki itwiki eswiki frwiki dewiki ptwiki`.
- Lua emits tags through `frame:extensionTag`, never as literal strings. Text parameters pass through as wikitext (no escaping), like `SV cite`.
- Category links are written `[[:Category:<name>|<label>]]` and memberships `[[Category:<name>]]` — the canonical `Category` namespace name works on every language wiki.
- Secrets: `~/.config/seminaverbi/editor.env` (mode 600) holds `SV_EDITOR_USER` and `SV_EDITOR_PASSWORD`. Never `cat`, print, echo, log or commit its values; never put them in `~/.claude.json`. Error messages never include the password.
- The bot never gets `sysop`, `bureaucrat`, `interface-admin`; its bot password never gets delete/protect/block/user-rights grants.
- MCP server pinned to `@professional-wiki/mediawiki-mcp-server@0.21.0` (MIT).
- Change tag `seminaverbi-mcp` on every MCP and `tools.categories` edit.
- `tools.categories` never edits an existing page.
- Server access: `ssh ubuntu@catholicdigitalcommons.org`; MW root `/var/www/vhosts/bibleget.io/seminaverbi_1_44/w`; run maintenance as `sudo -u bibleget.io_q71zp2mh9vh /opt/plesk/php/8.4/bin/php maintenance/run.php <script> --wiki=<code> …` (script name **before** `--wiki`). Never print LocalSettings DB lines.
- Full suite: `.venv/bin/pytest -q` from the repo root; it must stay green after every task.

## Review Focus

1. A tree category page that exists on a wiki as a **redirect** (e.g. after moving `Hitory`) — the check reports it as `redirect`, `--create` does not overwrite it.
2. Counterpart category pages on different wikis already attached to **different** Wikibase items — `--create` reports the conflict and sets no sitelink for that node.
3. `SV cathopedia` / `SV quote` called without their required parameter — a visible localized error, no Lua error, no broken link.
4. A login failure or API error in `tools.categories` — exit code 1 and a message that never contains the password.
5. Category or theme names containing `&`, `'` or parentheses (`Drama (Literature)`) — rendered links and page titles stay correct.
