# SeminaVerbi shared templates

The `SV …` templates and `Module:SV/…` Lua modules used on every SeminaVerbi wiki
(`en it es fr de pt`.seminaverbi.bibleget.io). **This repository is the source of truth:** the
pages on the wikis are overwritten by the sync script, so edit them here and open a pull request.

- `modules/SV/*.lua` → `Module:SV/*`
- `templates/<name>.wikitext` → `Template:<name>` (and `templates/SV infobox/styles.css` → TemplateStyles)
- `config/*.json` and `i18n/*.json` → compiled into `Module:SV/Data`
- `config/categories.json` → the category tree (fields + Gospel themes, six languages), also compiled into `Module:SV/Data`
- `server/` → maintenance script that fills Wikibase items from Wikidata (runs on the server)
- `skills/seminaverbi-editor/` → the Claude Code skill for editing the wikis through the `seminaverbi` MCP server
  (`mcp/`); `templates.md` and `categories.md` are generated by `python -m tools.skilldocs`
- `tools/categories.py` → checks a wiki's categories against the tree and creates the missing ones
- `tools/cleanup_articles.py` → converts old Bible quote and reference-list calls to the SV templates and
  removes Wikipedia's page-maintenance templates (`config/cleanup.json`); dry run by default

Design: `docs/superpowers/specs/2026-11-14-shared-templates-design.md`,
`docs/superpowers/specs/2026-11-17-wiki-mcp-design.md`.

## Editing the wikis with Claude Code

Install the skill once: `ln -s "$PWD/skills/seminaverbi-editor" ~/.claude/skills/seminaverbi-editor`.
The MCP server is described in `mcp/README.md`. After changing `config/templates.json`,
`config/categories.json`, aliases or i18n, run `python -m tools.skilldocs` (the tests fail if the
generated files are stale).

Category check, with the editor bot's credentials (`SV_EDITOR_USER` / `SV_EDITOR_PASSWORD`):

```
python -m tools.categories check --wiki fr [--create] [--dry-run]
```

## The category tree on the main pages

Each wiki's main page ends with `{{SV category tree}}` (`modules/SV/Categories.lua`): a card per
top-level field, collapsible branches, the Gospel themes as chips, and article counts.

- **Counts** come from `mw.site.stats.pagesInCategory`, an expensive parser function: one call per
  category, about 190 per page. The farm's `LocalSettings.php` raises `$wgExpensiveParserFunctionLimit`
  to 300 for this. A failed or over-limit lookup shows no count rather than an error. Counts are computed
  when the page is parsed, so a cached main page costs nothing; purge it to refresh them.
- **Only articles count.** `{{SV infobox}}` and `{{SV categories}}` file the field and theme categories
  in the main namespace only, so a sandbox or template page showing an item's infobox stays out.
- **TemplateStyles on the farm rejects `var()`**, and one bad value makes the sync refuse the whole
  stylesheet (the old one stays live). Use plain colours.
- **Night mode:** style it under `html.skin-theme-clientpref-night` and, inside
  `@media (prefers-color-scheme: dark)`, `html.skin-theme-clientpref-os`. The site's night-mode rule
  for the main page resets the background of every element except `.notheme`, so the cards, chips and
  badges carry `notheme`; Vector then gives `.notheme` the day text colour, so the night palette sets the
  text and link colours too. Check the page in both themes after a change.

## Test

```
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/pytest -q
```

Lua runs under Lua 5.1 (Scribunto's dialect) through `lupa`, with stubs for `mw`,
`mw.wikibase` and `mw.language` in `tests/lua_env.py`.
